# Upgrading to v0.25

## Bump Your Deps

Update Backpex to the latest version:

```elixir
defp deps do
  [
    {:backpex, "~> 0.25.0"}
  ]
end
```

## Selects and multi selects render a combobox

The forms of these fields and filters rendered a native `<select>` or a dropdown with checkboxes. The multi select
field sent an event to the server for every option an admin toggled, and each of them had its own markup, keyboard
handling and search. They now all render `Backpex.HTML.Combobox.combobox/1`:

- `Backpex.Fields.Select` and `Backpex.Fields.BelongsTo`, in the form and in the index form (`index_editable`)
- `Backpex.Fields.MultiSelect` and `Backpex.Fields.HasMany`
- the select of the related record in the modal of `Backpex.Fields.HasManyThrough`
- `Backpex.Filters.Select` and `Backpex.Filters.MultiSelect`

The options of the fields and the callbacks of the filters are unchanged, and the forms submit the same params. An
admin selects and deselects options in the browser, and the selection reaches the server with the `phx-change` event
of the form. The combobox needs the `BackpexCombobox` hook, which is part of the Backpex hooks, so there is nothing to
add to your `app.js`.

What you may have to change:

- **Markup and ids.** There is no `<select>`, `<option>` or checkbox any more, and the elements with the ids
  `has-many-dropdown-<name>` and `multi-select-<id>` are gone. The combobox has the id of its form field, e.g.
  `resource-form_tags` or `filter-form_category_id`, and its parts have the ids `<id>-trigger`, `<id>-popup`,
  `<id>-search` and `<id>-listbox`. Update CSS and JavaScript that target the old markup.
- **The `prompt` of `Select` and `BelongsTo`** is shown while no option is selected and is no option with an empty
  value any more. A field with a `prompt` has a button that clears the selection. A field without a `prompt` still
  selects its first option while the item has no value, like the native select did.
- **`debounce: "blur"`** of `Select` and `BelongsTo` sends the change when the focus leaves the combobox.
- **`Backpex.Fields.MultiSelect`:** "Select all" and "Deselect all" are two buttons that apply to the options the
  search currently shows, not to all options.
- **`Backpex.Fields.HasMany`:** the field handles the search of the combobox, so its `"search"` event takes
  `%{"query" => query}` instead of the value of the removed search input `<name>_search`.

### Tests

`PhoenixTest.select/3` and `PhoenixTest.check/2` find no native control for these fields and filters, and
`Phoenix.LiveViewTest.form/3` can't fill in the values of `MultiSelect` and `HasMany`, as the hook adds their inputs in
the browser. Send the values as params instead. `Backpex.Testing.submit_form/3` and
`Backpex.Testing.confirm_item_action/2` take the value of a select and a list of values for a field with multiple
values:

```elixir
# before
session
|> select("Category", option: "News")
|> check("Elixir")
|> click_button("Save")

# after
Backpex.Testing.submit_form(view, %{category_id: category.id, tags: [tag.id]})
```

To send a change of one field, pass its params to the event of the form:

```elixir
view
|> form("#resource-form")
|> render_change(%{"change" => %{"tags" => [tag.id]}, "_target" => ["change", "tags"]})

view
|> form("#filter-form")
|> render_change(%{"filters" => %{"user_id" => [user.id]}})
```

In a browser test, click the trigger (`#<id>-trigger`) and then the option (`#<id>-listbox [role=option]`).

## New option `searchable_options`

`Backpex.Fields.Select`, `Backpex.Fields.BelongsTo` and `Backpex.Fields.HasManyThrough` take the new option
`searchable_options`. With `true`, the combobox has a search input that filters its options:

```elixir
category: %{
  module: Backpex.Fields.BelongsTo,
  label: "Category",
  display_field: :name,
  searchable_options: true
}
```

It is `false` by default, so these selects look like before. Like a native select, a combobox without a search input
jumps to the option that starts with the typed characters. The general field option `searchable` is unrelated: it
makes a field searchable on the index view.

## The `multi_select` component is removed

No built-in field renders the `multi_select/1` component of `Backpex.HTML.Form` any more, and
`Backpex.HTML.Combobox.combobox/1` does the same without events for the selection. Replace it in your custom fields
and remove the handlers of its events `toggle-option` and `toggle-select-all`, and of `search` unless the options are
searched on the server:

```elixir
# before
<Backpex.HTML.Form.multi_select
  field={@form[@name]}
  options={@options}
  selected={@selected}
  prompt={@prompt}
  not_found_text={@not_found_text}
  search_input={@search_input}
  show_select_all={@show_select_all}
  show_more={false}
  event_target={@myself}
  field_options={@field_options}
  live_resource={@live_resource}
/>

# after
<Backpex.HTML.Combobox.combobox
  field={@form[@name]}
  options={@options}
  multiple
  select_all
  placeholder={@prompt}
  no_results_text={@not_found_text}
  live_resource={@live_resource}
  aria-labelledby={@label_id}
/>
```

The combobox reads the selection from the form field and searches the rendered options in the browser. `select_all`
adds the buttons to select and deselect all options, and the `:header` and `:footer` slots take further content like a
"Show more" button. With `on_search` it searches on the server.
See `Backpex.HTML.Combobox` and [custom fields](custom-fields.md).

## Filters receive their label

`c:Backpex.Filter.render_form/1` receives the label of the filter as `@label`. The built-in select filters use it as
the accessible name of their combobox. If your filter module overrides `render_form/1` and calls
`Backpex.Filters.Select.render_form/1` or `Backpex.Filters.MultiSelect.render_form/1` with assigns of its own, pass
`label` on. Without it the combobox is named by the prompt.
