# Upgrading to v0.25

## Bump Your Deps

Update Backpex to the latest version:

```elixir
defp deps do
  [
    {:backpex, "~> 0.25.0"}
  ]
end
```

## Filter, metric, action and panel configurations are validated

Before v0.25, Backpex only validated the options of fields. The maps returned by `filters/0,1`, `metrics/0`,
`item_actions/1` and `resource_actions/0` and the keyword list returned by `panels/0` were read as they are: a typo
such as `lable:` or `preset:` was silently ignored, and a missing `:label` or `:select` of a metric raised a `KeyError`
while the index view was rendered.

Backpex now validates these configurations when the view loads and raises an `ArgumentError` that names the
LiveResource, the entry and the key:

```
** (ArgumentError) Configuration error for filter "published" in "Elixir.MyAppWeb.PostLive".

unknown options [:lable], valid options are: [:module, :label, :default, :presets]
```

Fix the key the error names, or remove it if nothing reads it. The valid options are:

| Callback             | Options                                                                              |
| -------------------- | ------------------------------------------------------------------------------------ |
| `filters/0,1`        | `:module` (required), `:label`, `:default`, `:presets` (maps with `:label` and `:values`) |
| `item_actions/1`     | `:module` (required), `:only`, `:except` (lists of `:row`, `:index`, `:show`)        |
| `resource_actions/0` | `:module` (required)                                                                 |
| `panels/0`           | a keyword list of `name: "Label"`, the label is a string                             |
| `metrics/0`          | `:module` (required), `:select` (required unless the metric module implements `data/2`); for `Backpex.Metrics.Value` also `:label` (required), `:format`, `:class` |

A metric of `Backpex.Metrics.Value` no longer needs `format: nil` to show the value as it is: leave `:format` out.

If you have a metric module of your own that reads further keys from its map, nothing changes: Backpex validates
only `:module` and `:select` and passes the other keys on. To have these keys validated too, implement
`c:Backpex.Metric.config_schema/0` in the metric module:

```elixir
@impl Backpex.Metric
def config_schema do
  [
    label: [type: :string, required: true],
    color: [type: {:in, [:primary, :secondary]}]
  ]
end
```

Filter, item action and resource action modules do not receive their map, so a key of your own in it was never
read. Move such a value into the module.
