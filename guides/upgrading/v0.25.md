# Upgrading to v0.25

## Bump Your Deps

Update Backpex to the latest version:

```elixir
defp deps do
  [
    {:backpex, "~> 0.25.0"}
  ]
end
```

## `postgrex` is an optional dependency and `phoenix_html_helpers` is gone

Backpex used each of the two packages in one place: `postgrex` to recognize a foreign key violation when deleting
items, `phoenix_html_helpers` to render the hidden inputs of the `Backpex.Fields.HasManyThrough` form. Both places work
without the package now, so Backpex no longer adds them to your application.

Backpex still needs PostgreSQL. An application with an `Ecto.Adapters.Postgres` repository lists `postgrex` itself, as
`mix phx.new` generates it; make sure it is in your `mix.exs`:

```elixir
defp deps do
  [
    {:postgrex, ">= 0.0.0"}
  ]
end
```

If your own code calls `PhoenixHTMLHelpers` and got the package only through Backpex, add it too:

```elixir
defp deps do
  [
    {:phoenix_html_helpers, "~> 1.0"}
  ]
end
```

## Unused pagination and order helpers removed from `Backpex.LiveResource`

The index view validates its pagination, order and search params with `Backpex.PaginationValidation`. These public
helpers of `Backpex.LiveResource` were no longer called by Backpex and are removed:

- `order_options_by_params/4`
- `parse_integer/3`
- `validate_page/2`
- `value_in_permitted_or_default/3`

`order_options_by_params/4` also converted the `order_by` and `order_direction` params with
`String.to_existing_atom/1`, which raises for a param that is not an existing atom.

If your app calls one of them, use `Backpex.PaginationValidation` instead: `build/2` validates `page`, `per_page`,
`order_by` and `order_direction` against your options (with `init_order` already resolved to a map) and falls back to
defaults for invalid values, and `clamp_page/2` replaces `validate_page/2`. `parse_integer/3` and
`value_in_permitted_or_default/3` have no replacement; they are small enough to copy into your app.

## Filter, metric, action and panel configurations are validated

Before v0.25, Backpex only validated the options of fields. The maps returned by `filters/0,1`, `metrics/0`,
`item_actions/1` and `resource_actions/0` and the keyword list returned by `panels/0` were read as they are: a value
of the wrong type was passed on, and a missing `:label` or `:select` of a metric raised a `KeyError` while the index
view was rendered.

Backpex now validates these configurations when the view loads and raises an `ArgumentError` that names the
LiveResource, the entry and the key:

```
** (ArgumentError) Configuration error for metric "total" in "Elixir.MyAppWeb.PostLive".

unknown options [:lable], valid options are: [:module, :label, :select, :format, :class]
```

Fix the key the error names, or remove it if nothing reads it. Backpex validates these options:

| Callback             | Options                                                                              |
| -------------------- | ------------------------------------------------------------------------------------ |
| `filters/0,1`        | `:module` (required), `:label`, `:default`, `:presets` (maps with `:label` and `:values`, nothing else) |
| `item_actions/1`     | `:module` (required), `:only`, `:except` (lists of `:row`, `:index`, `:show`)        |
| `resource_actions/0` | `:module` (required)                                                                 |
| `panels/0`           | a keyword list of `name: "Label"`, the label is a string or `nil`                    |
| `metrics/0`          | `:module` (required), `:select` (required unless the metric module implements `data/2`) |

A filter, item action, resource action or metric module can read its whole map, so further keys in it are options of
the module and are passed on as they are. Some modules declare their options, and then any other key raises:

- `Backpex.Metrics.Value` takes `:label` (required), `:format` and `:class` (string, list or `nil`).
- The default item actions `Backpex.ItemActions.Show`, `Backpex.ItemActions.Edit` and `Backpex.ItemActions.Delete`
  take no further option.

A metric of `Backpex.Metrics.Value` no longer needs `format: nil` to show the value as it is: leave `:format` out.

To have the keys of a module of your own validated too, e.g. to catch a typo, implement `config_schema/0` in the
module (`c:Backpex.Filter.config_schema/0`, `c:Backpex.ItemAction.config_schema/0`,
`c:Backpex.ResourceAction.config_schema/0` or `c:Backpex.Metric.config_schema/0`):

```elixir
@impl Backpex.Metric
def config_schema do
  [
    label: [type: :string, required: true],
    color: [type: {:in, [:primary, :secondary]}]
  ]
end
```
