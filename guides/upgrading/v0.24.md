# Upgrading to v0.24

## Bump Your Deps

Update Backpex to the latest version:

```elixir
defp deps do
  [
    {:backpex, "~> 0.24.0"}
  ]
end
```

## The forms of `BelongsTo` and `HasManyThrough` only save options

The `options_query` of `Backpex.Fields.BelongsTo` and `Backpex.Fields.HasManyThrough` only limited the options of the
select, so a crafted request could save any record. The forms now check the submitted records against the options
query, as the form of `Backpex.Fields.HasMany` and the index form of `Backpex.Fields.BelongsTo` already do:

- `BelongsTo` saves an option, no option, or the value the item already has.
- `HasManyThrough` links options and keeps the records the item is already linked to.

Any other record gets the error `"is invalid"`, so a save that went through before can now be refused. This affects
you if your code or your tests submit a record the select doesn't offer, e.g. one beyond a `limit` of the options
query. Widen the `options_query` to every record the field may be set to.

The check only runs for a field that is part of the form and not readonly, so keep validating the value in your
changeset where it matters.
