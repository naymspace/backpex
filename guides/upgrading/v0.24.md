# Upgrading to v0.24

## Bump Your Deps

Update Backpex to the latest version:

```elixir
defp deps do
  [
    {:backpex, "~> 0.24.0"}
  ]
end
```

## Upload fields store the files before the item is saved

`consume_upload` now runs before the item is saved, so it gets the item from before the save: on edit the item without
its changes, on create the new empty item. On create, `item.id` is `nil`, and a path built from it is wrong without an
error (`"avatars/#{item.id}/#{file_name}"` becomes `avatars//photo.jpg`). Take the file name from the entry instead, for
example `entry.uuid` as in the examples of `Backpex.Fields.Upload`, the same name `put_upload_change` puts into the
params. If the path has to contain the id, move the file in `c:Backpex.LiveResource.on_item_created/2` and update the
column there as well, which is a second write. A resource action still passes the data of the form.

Before v0.24, the form saved the item first and called `consume_upload` afterwards, outside of any transaction, and
ignored what it returned. When a file couldn't be stored (a full disk, an object store that's down), the item
referenced a file that didn't exist, the form showed a success message, and `remove_uploads` still deleted the file the
failed upload was meant to replace.

The form now saves in this order:

1. It checks that the user may save the item and builds the changeset. If the changeset is invalid, the form shows the
   errors and stores no files.
2. It calls `consume_upload` for one entry after the other. At the first file that can't be stored, it stops.
3. It saves the item. In a resource action, it runs `handle/2`.
4. After a successful save, it calls `remove_uploads` for the files the user removed. If the save fails, or `handle/2`
   returns an error, it calls the new `discard_uploads` for the files of step 2 instead.

What changes for upload fields:

- Return `{:error, reason}` from `consume_upload` when a file can't be stored. Backpex logs the reason, doesn't save
  the item, shows "file could not be stored" at the field, discards the files of the same form that were already stored
  and keeps the uploaded files in the form, so the user can save again. An exception and `{:postpone, value}` count as
  a file that wasn't stored, too. Any other return value counts as stored, with a warning in the log.
- `consume_upload` may run again for the same entry: after a failed save, the next save stores the files again under
  the same names. The write has to work when the file exists already, or treat an existing file as stored.
- The new optional `discard_uploads` function deletes the files that `consume_upload` stored when the item can't be
  saved afterwards, for example because of a unique constraint. It gets the values `consume_upload` returned in
  `{:ok, value}`, so return what you need to find the file again. Without `discard_uploads`, these files stay and
  Backpex logs a warning. Direct uploads (`external`) aren't discarded, because the browser uploaded them before the
  save and the next save uses them again.
- The form checks `can?/3` for `:new` or `:edit` before it stores any file, in addition to the check when the item is
  saved.

```elixir
images: %{
  module: Backpex.Fields.Upload,
  # ...other options
  consume_upload: &consume_upload/4,
  discard_uploads: &discard_uploads/3
}
```

```elixir
defp consume_upload(_socket, _item, %{path: path} = _meta, entry) do
  file_name = file_name(entry)

  with :ok <- File.cp(path, Path.join(upload_dir(), file_name)) do
    {:ok, file_name}
  end
end

defp discard_uploads(_socket, _item, file_names) do
  for file_name <- file_names, do: File.rm(Path.join(upload_dir(), file_name))
end
```

A custom upload field that implements the upload callbacks gets the new optional callback
`c:Backpex.Field.discard_uploads/4` instead. If you translate Backpex's texts, add a translation for "file could not be
stored" in `backpex.pot`.

Forms that have uploaded files build the changeset twice now, once before the files are stored and once when the item
is saved, so `before_changeset` callbacks of their fields run twice as well.
