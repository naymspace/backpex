# Upgrading to v0.24

## Bump Your Deps

Update Backpex to the latest version:

```elixir
defp deps do
  [
    {:backpex, "~> 0.24.0"}
  ]
end
```

## Forms save only the params of fields an admin may edit

Before v0.24, the form passed every param of the client to the changeset, except the params of readonly fields. A
crafted client could change a value through a field that `can?`, `only` or `except` hides from the admin, or through a
column the LiveResource has no field for, whenever the changeset casts it.

The form now passes only the params of the fields of the current view that `can?` allows and that are not readonly.
Backpex drops every other param before it calls `c:Backpex.Field.before_changeset/6` and the changeset.

A field submits the param of its name by default, e.g. `change[title]`. If a custom field renders inputs under other
names, return all of them from the new `c:Backpex.Field.param_keys/2` callback, or the form drops them:

```elixir
@impl Backpex.Field
def param_keys({name, _field_options}, _assigns) do
  name = Atom.to_string(name)

  [name, name <> "_confirmation"]
end
```

The built-in fields return their params already, e.g. `Backpex.Fields.BelongsTo` the foreign key of the association.
If your changeset needs a value that no field of the form submits, set it on the server instead of rendering an input
for it: in the changeset from the `:assigns` of its metadata, or in `c:Backpex.LiveResource.on_item_creating/2` and
`c:Backpex.LiveResource.on_item_updating/2`, which receive the change before it is saved.

`Backpex.Field.drop_readonly_changes/3` now also drops the params a readonly field returns from `param_keys/2`, e.g.
the foreign key of a readonly `Backpex.Fields.BelongsTo` field.
